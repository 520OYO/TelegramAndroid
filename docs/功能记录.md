## 详情

### 2026-11-26 基线：App 内填值链路

- **加了什么**
  - 新增 `org.telegram.messenger.forkgram.ApiCredentials`：负责 api_id / api_hash 的读写与校验。
  - 新增 `org.telegram.ui.ApiCredentialsActivity`：设置页输入界面（两个输入框 + 右上角 Done）。
  - `BuildVars` 新增 `loadRuntimeCredentials(Context)`；`APP_ID` / `APP_HASH` 注释标明是编译期占位。
  - `ApplicationLoader.onCreate()` 在 `NativeLoader.initNativeLibs()`（原 394 行）之前调用 `BuildVars.loadRuntimeCredentials(applicationContext)`。
  - `ForkSettingsActivity` 新增分组「API Credentials」（`ID_API_CREDENTIALS = 104`）与点击分支。
- **存在哪**
  - 存储用普通 `SharedPreferences`，文件 `mainconfig`，键 `custom_api_id`（int）、`custom_api_hash`（String）。不引入加密依赖。
- **怎么生效**
  - 保存后必须**重启 App**：`api_id` 会被 native 层缓存（`ConnectionsManager.cpp` 的 `currentApiId`），热改无效。
  - 两个输入框都留空并按 Done → 删除覆盖值，回落到编译期占位。
  - 未配置时不崩溃：只保留占位值，登录会失败但 App 正常启动。
- **没动的地方**
  - `TMessagesProj/jni/tgnet/**` 零改动（`api_hash` 在 C++ 侧无引用，`api_id` 只是被 `init()` 传入后缓存）。
  - 全部 10 处 Java 使用点（`ConnectionsManager`、`LoginActivity`、`PasskeysController` 等）零改动，运行时读的就是被覆盖后的静态字段。
  - `.github/workflows/tandroid.yml` 未改动：现有流程已把 `secrets.APP_ID` / `secrets.APP_HASH` 写进 `gradle.properties`；Secrets 缺值时写 0 或空，App 内设置页正好覆盖，逻辑自洽。

### 2026-11-26 G 去谷歌：移除 GMS / Firebase

- **甄别结论（重要）**：全仓 Java/Kotlin 层 **0 处真实 GMS / Firebase 调用**。
  - 13 个 grep 命中文件里 12 个只是注释、字符串常量或 MTProto 协议命名（`TL_auth_sentCodeTypeFirebaseSms` 之类），与 GMS 无关。
  - `PushListenerController` 的 `FirebaseApp.initializeApp` / `FirebaseMessaging.getInstance().getToken()`（原 1853-1854 行）**整段被 `/* */` 包住**，`GooglePushListenerServiceProvider.hasServices()` 也已是 `return false`。
  - `ConnectionsManager.onIntegrityCheckClassic()` 与 `LoginActivity.fillNextCodeParams()` 里的 `IntegrityManagerFactory` / `SafetyNet.getClient` 同样**全在注释块内**（`LoginActivity` 注释块 1789–1907 行）。
  - 因此本次只动构建层，**零 Java 逻辑改动、零崩溃风险**。
- **改了哪里**
  - `TMessagesProj/build.gradle`：删 `com.google.android.play:integrity:1.3.0`、`com.google.android.gms:play-services-safetynet:18.0.1`、`androidx.credentials:credentials-play-services-auth:1.6.0-alpha04`；保留 `androidx.credentials:credentials` 主包（Passkeys 编译依赖）。
  - `AndroidManifest.xml`：删 `com.google.android.gms.cast.framework.OPTIONS_PROVIDER_CLASS_NAME` meta-data（`ChromecastOptionsProvider` 整个类本来就是注释状态，指向的类根本不存在）。
  - `TMessagesProj_AppStandalone/build.gradle`：删 `apply plugin: 'com.google.gms.google-services'`。
  - 删除三份 `google-services.json`（`TMessagesProj/`、`TMessagesProj_App/`、`TMessagesProj_AppStandalone/`）。仓库未提交任何 keystore。
  - 根 `build.gradle` 的 `google()` Maven 仓库**保留**：AndroidX 等依赖仍从该仓库取，删了会拖慢/打断构建，且不影响 APK 内是否含 GMS。
- **推送行为**：首包**无 Google 推送**。`GooglePushListenerServiceProvider.hasServices()` 恒为 false，不会被选中；UnifiedPush 分发器缺失时也不会崩，最坏情况是前台/轮询收消息。
- **Passkeys**：移除 Play Services 提供的凭据实现后，`CredentialManager` 调用可能抛 `NoCredentialException`，已被 `PasskeysController` 的 `try/catch` 兜住，退回验证码/密码登录，不崩。
- **CI 出包（本次同时解决）**：普通 push（commit message 不含 `[Release]` / `[Optional]`）时 `mode=ci`，原流程既不上传 artifact 也不签名（旧的 `sign` job 还硬编码校验正式证书指纹，无 secrets 必红）。现新增：`mode=ci` 时自动用**临时 debug keystore** 对 `app.apk` 做 zipalign + apksigner 签名，产出 artifact `android-installable-apk`（`installable/ForkClient-ci.apk`），可直接安装到手机。原 `sign` / `publish-*` job 一行未改。

### 2026-11-26 CI 整数构建字段兜底（`612908c`）
- **问题**：CI 里 `secrets.APP_ID` 缺失时，`gradle.properties` 写出空字符串，`BuildConfig.APP_ID` 这类 `int` 字段直接编译失败。
- **改法**：`.github/workflows/tandroid.yml` 用 `${APP_ID:-0}` / `${APP_HASH:-}` 形式兜底，缺失时写 `0` / 空串，保证 `int` 字段能编译。
- **影响面**：只动 workflow 两个赋值，不动 Java 代码。缺失 Secrets 时 `APP_ID=0`，服务器必然拒绝登录 —— 这正是后面「填值链路必须在登录前可用」的前置背景。

### 2026-11-26 急修死锁：登录前填 API 凭据（v2）
- **现象**：装 G 出的基线包后，扫码登录弹 `CONNECTION_API_ID_INVALID`；输手机号点下一步无反应、无提示。
- **根因（死锁）**：登录流程开始前 `tgnet` 就要用 `BuildVars.APP_ID` / `APP_HASH` 建连，而这两个值是编译期占位（CI 无 Secrets 时为 `0` / 空，本地为伪值），服务器必拒；而唯一能改值的「API Credentials」页挂在**登录之后**的 Fork 设置里 → 永远进不去，永远改不了。
- **修复（不动 jni、不动占位值，只改入口时序）**
  - 新增 `org.telegram.ui.FirstRunSetupActivity`：**独立 Activity**，用系统主题（`Theme_DeviceDefault_Light_NoActionBar`），纯代码搭 UI，不依赖仓库内 Telegram 主题/主题资源。三档中文校验：空值 → 「请先填 API 凭据：api_id 和 api_hash 都不能为空」；非正整数 → 「api_id 必须是不小于 1 的整数」；非 32 位十六进制 → 「api_hash 必须是 32 位十六进制字符」。未配置时**拦截返回键**，只弹 Toast，防止退回死锁。
  - `LaunchActivity.onCreate` 最早处（`activeInstanceCount++` 之后、`postInitApplication()` 之前）加分流：`!ApiCredentials.hasCredentials()` → 起 `FirstRunSetupActivity` 并 `finish()`，**根本不进登录/连接流程**。
  - `LoginActivity` 左上角加 ⚙ 入口（返回键右侧 56dp 处）：用 `TextView` 画字符实现，**零新增 res 资源**（工作区是 sparse-checkout，`src/main/res` 未检出，新增资源会炸构建）；点击起同一个 `FirstRunSetupActivity`，随时可改 api_id。
  - `ApiCredentials` 新增 `restartApp(Context)`：`AlarmManager` 预约启动（400ms）+ `Handler.postDelayed` 250ms 后 `killProcess` 重启进程 —— 因为 `APP_ID`/`APP_HASH` 是静态字段、native 侧启动时缓存 apiId，只重启 Activity 不生效。
  - `ApiCredentials.prefs()` 改为**优先直接打开 `mainconfig`**（与 `MessagesController#mainPreferences` account 0 同一个文件），避免首次配置页这种极早期时机去构造 `MessagesController` 实例；拿不到 context 才回落原路径。
  - `TMessagesProj/src/main/AndroidManifest.xml` 注册 `FirstRunSetupActivity`（`exported="false"`）。
- **时序确认**：`ApplicationLoader.onCreate` 中 `BuildVars.loadRuntimeCredentials()`（第 396 行）确实早于 `NativeLoader.initNativeLibs()`（第 398 行）与 `ConnectionsManager.native_setJava()`（第 401 行），读配置时机无需改动。
- **没动的地方**：`TMessagesProj/jni/**` 零改动；`BuildVars` 编译期占位值未改；A（系统本地 TTS）、D/B/E/F 全部未碰。

- 菜单显示修复：长按菜单里朗读项按「有没有可用引擎」决定是否显示，不再出现「看不见」或「点了没反应」。

**三、AI 模型可用性（`dcdc1e8`，6 文件 +464/-8）**
- 新增 `AiFlags` 总开关：关掉后所有 AI 入口（AI 助手、翻译、朗读以外的对话）一律不发起请求，只提示已关闭。
- 新增 `FeatureModelDialog`：为各功能**分别指定**模型（询问/图片/翻译/对话各挑一条），互不影响；未指定时明确提示「这个功能还没指定模型」。
- AI 对话从弹窗改为 `AiChatPage` 独立页面，支持连续追问、历史留在内存、可清空。

**四、上传入口挪到频道（`4af4c7f`，4 文件 +169/-15）**

- `BackupConfig` 新增照片/视频/音乐三类频道与日志频道；`BackupUploader.sendOne` 统一**不带 caption**，素材只发媒体本身。
- `BackupConfigDialog` 相应改写，日志频道可查看、默认黑名单。

**五、AI 对话频道权限 + 搜索代发（`138d8f4`，5 文件 +1195/-27）**
- 新增 `AiPerm`：三模式（全部允许 / 只允许白名单 / 静默只读）+ 白名单 + 黑名单；名单只存本机 `SharedPreferences`（`ai_perm`），**不上传、不打印、不进日志**；黑名单永远优先；备份的日志频道自动算进黑名单（`isBackupLogChannel`）。
- 新增 `AiChannelTools`：`listChannels` 列可读频道、`searchAsync` 走 `MediaDataController.searchMessagesInChat` 在频道内搜索（等价官方「频道内搜索」，带 8 秒超时与单次回调保护）、`sendText` 真发消息并带五重兜底（空文本 / `dialogId==0` / 无发权限 / 聊天已关 / `canWriteToChat` 为假）。
- 新增 `AiChannelPicker`：频道选择器，可搜名字、置顶「不使用频道（纯聊天）」，只读频道点了明确提示「只能读，不能发」。
- 新增 `AiPermDialog`：权限设置界面，改完立刻重开选择器、列表按新权限刷新。
- `AiChatPage`：顶栏新增「频道」入口 + 状态行；发送前先过读权限；`chan==0` 为纯聊天，选了频道则**先搜该频道再回答**，搜不到自动换个词再搜一次，两次都空给出中文提示；回答下方出现「✈ 发到「频道名」」按钮，点击弹**中文确认框**（300 字内容预览 + 「发出去就撤不回」），确认后才真发，成功后按钮置灰变「✔ 已发到…」。
- 设计取向：**先搜再答，不许凭空编**；写操作一律二次确认，且权限不放行时连按钮都不出现。


## 长期备忘（约束，不得违背）

1. **素材频道只发纯媒体**：上传到素材频道的内容只发媒体本身，**不带文件名、不带 caption、不带任何说明文字**。
2. **日志频道默认加入黑名单**：日志频道默认进黑名单，防止后续 AI 读取频道历史时把日志当素材处理。
3. 真实密钥（api_id / api_hash / 模型 key）只存 App 本地 `SharedPreferences`，不写进源码、不打印、不进构建日志。
4. 默认不动 `TMessagesProj/jni/**` 下的 C/C++；自定义 HTTP 统一走 `HttpURLConnection`（本仓库无 OkHttp）。
